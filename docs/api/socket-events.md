# Socket.IO Event Reference

## Overview

The Falcon platform uses Socket.IO to provide low-latency, bidirectional communication between browser clients and the Falcon Gateway.

Socket.IO is responsible for:

• Browser connectivity

• Flight command delivery

• Live telemetry

• Fleet synchronization

• Command acknowledgements

• Gateway notifications

The browser communicates only with the Falcon Gateway. Aircraft communication is handled separately through MQTT.

# Client → Gateway Events

## drone:command

Description

Sends a flight command to a specific aircraft.

Example

```json
{
  "droneId": "falcon-05",
  "command": "START_MISSION",
  "parameters": {},
  "timestamp": "2026-07-29T18:45:22Z"
}
```

Possible Commands

• START_MISSION

• PAUSE_MISSION

• RESUME_MISSION

• HOVER

• RETURN_TO_HOME

• LAND

• SET_ALTITUDE

• SET_HEADING

---

# Gateway Acknowledgement

Every drone:command event returns an acknowledgement.

Example

```json
{
  "success": true,
  "command": "LAND",
  "commandId": "7fa3d821",
  "message": "Command accepted."
}
```

Possible Results

• success = true

• success = false

# Gateway → Client Events

## telemetry:update

Description

Broadcasts live aircraft telemetry.

Example

```json
{
  "telemetry": {
    "...": "..."
  }
}
```

Published

Continuously

Purpose

Updates the Drone Console.

---

## fleet:snapshot

Description

Provides a snapshot of all currently connected aircraft.

Example

```json
[
  {
    "telemetry": {}
  }
]
```

Purpose

Synchronizes newly connected clients.

---

## drone:command-status

Description

Reports execution status from the aircraft.

Example

```json
{
  "droneId": "falcon-05",
  "command": "LAND",
  "status": "ACCEPTED",
  "message": "Landing initiated."
}
```

Possible Status Values

• ACCEPTED

• REJECTED

• FAILED

---

## command:dispatched

Description

Generated by the Falcon Gateway after a command has been successfully published to MQTT.

Example

```json
{
  "droneId": "falcon-05",
  "command": "LAND"
}
```

Purpose

Confirms successful routing.

---

## command:error

Description

Reports gateway-side errors.

Example

```json
{
  "message": "Drone not connected."
}
```

Typical Causes

• Unknown aircraft

• MQTT unavailable

• Invalid command

• Gateway failure

---

# Connection Events

## connect

Generated automatically when the browser successfully connects.

---

## disconnect

Generated automatically when the connection closes.

---

## connect_error

Generated when the browser cannot establish a Socket.IO connection.

Typical causes include:

• Gateway unavailable

• Network interruption

• TLS failure

# Error Handling

The Falcon Gateway validates every incoming command before publishing it.

Validation includes:

• Drone identifier

• Command type

• Parameter validation

• MQTT availability

• Aircraft availability

Invalid requests generate command:error responses.

# Design Principles

The Falcon Socket.IO API follows several principles.

• Event-driven

• Low latency

• Stateless messaging

• JSON payloads

• Real-time synchronization

• Backward compatibility

---

# Summary

Socket.IO provides the real-time browser interface for the Falcon platform.

By separating browser communication from MQTT messaging, the Falcon Gateway provides a scalable, secure, and extensible architecture that supports both current single-aircraft operations and future multi-aircraft fleet management.
